## One-line

A Claude Code skill that takes a Neuron kernel, has Claude generate optimization
variants, **automatically compiles them, verifies they're numerically correct, profiles
each on real hardware, diffs the results, and returns the fastest correct version** —
the closed loop AWS's tools don't have. AWS *suggests* optimizations; this *applies, runs,
and proves* them.

## Problem Statement

Optimizing for AWS Neuron (Trainium / Inferentia) is high-toil and the feedback loop is
manual. Capturing a profile is ~7 steps and ~9 env vars (SSH to a `trn`/`inf2` box, set
env, run, convert to Perfetto, `find` NEFF/NTFF artifacts, copy to laptop, upload to a
web GUI). Worse, even after a tool tells you "this op is the bottleneck, try X," *you*
still hand-write the variant, recompile, re-run, manually check it's still correct, and
eyeball whether it got faster. Every tool stops at the suggestion. Nobody closes the loop.

Goal: an **open-source tool the Neuron community adopts**, delivered as a **Claude Code
skill**, that closes that loop autonomously.

## What Makes This Cool (the "whoa")

`/neuron-optimize <kernel>` → Claude proposes N rewrites → each is auto-compiled,
auto-verified for numerical correctness against the original, auto-profiled on real
silicon, and ranked → you get back the fastest *correct* variant plus a diff explaining
why it won. The developer watched an AI optimize their kernel end-to-end, with proof it
didn't break anything. That is a genuinely new thing to show someone.

## Landscape (research, 2026-06-06)

- **Neuron Explorer** — GA in SDK 2.29 (April 2026); the profiler. AI-powered bottleneck
  *recommendations* powered by Bedrock + **Claude Sonnet 4.5** (top 2–3 opts ranked by
  effort/impact). Single-profile, GUI-first. **Suggests; does not apply/run/compare.**
- **Neuron Agentic Development** — AWS's open-source package of AI agents + skills for
  Trainium, installable as a Claude Code plugin. Scoped to **NKI kernel authors** + HF→NxD
  porting. Skills: `neuron-nki-profiling` (captures traces, extracts JSON metrics),
  `neuron-nki-profile-querying` (SQL over profile data), `neuron-nki-profile-analysis-agent`
  (autonomously captures + identifies inefficiencies). **Analyzes; does not generate
  variants, verify correctness, or run a comparison loop.**
- **`neuron-profile` / Profiler 2.0** — deprecated, end-of-support in 2.29.

**EUREKA (logged):** Everyone in the Neuron tool stack stops at *suggesting*
optimizations (even AWS's Claude-powered Explorer). The durable, uncontested wedge is
the autonomous **closed loop**: generate → compile → verify-correct → profile → diff →
rank. Capture and diff are not the product; they are plumbing the loop rides on.

## Strategic shift (eyes open)

Rev 1 aimed capture at the **model-deployer** audience AWS's skills ignore. Leading with
**kernel** code-gen (this rev) re-aims at the **NKI kernel-author** audience — AWS's home
turf. We do not beat AWS at kernel *authoring*; we beat them at the *closed loop they
don't have*. This is a deliberate, accepted trade: smaller/expert audience, stronger and
more novel differentiation. (A later track can apply the same loop to model-level config,
re-reaching deployers — see Roadmap v4.)

## Constraints

- **Form factor:** Claude Code skill first. Parse / diff / cost / correctness-check logic
  lives in **standalone helper scripts the skill calls**, never in SKILL.md prose, so a
  headless CLI + GitHub Action is a later lift, not a rewrite.
- **Hardware:** every variant compiles and runs on a real `trn1`/`trn2`/`inf2` instance
  (~$1.3–$20+/hr). User has AWS access. **Cost control is a first-class design concern**
  (bounded N, early-stop, reuse one warm instance for a whole sweep).
- **Audience:** NKI kernel authors (this rev). Variant target = a single kernel/op with a
  clean reference output, not a whole model.
- **Reuse AWS where it already wins:** seed variants from Neuron Explorer / agentic-skill
  *suggestions* when available; reuse `neuron-nki-profiling` JSON for measurement. Don't
  rebuild capture or suggestion engines.

## The closed loop (core architecture)

```
seed: profiler suggestion (Explorer/agentic) OR "make this faster"
   │
   ▼
[1] GENERATE   Claude writes a kernel variant from the seed + original source
   │
   ▼
[2] COMPILE GATE   neuronx-cc compile. Fail → feed error back to [1], bounded retries (e.g. 3)
   │  pass
   ▼
[3] CORRECTNESS GATE   run variant + original on representative inputs;
   │                   assert outputs match within tolerance (rtol/atol). Fail → discard variant
   │  pass
   ▼
[4] PROFILE   capture profile.json for the variant (reuse neuron-profile / agentic skill)
   │
   ▼
[5] DIFF + RANK   compare profile.json vs baseline + other variants;
                  rank by latency (and later cost); keep Pareto-best CORRECT variant
   │
   ▼
report: winning variant + diff explaining why + correctness proof
```

The correctness gate [3] is the make-or-break component and is built **first**. A tool
that returns a fast-but-wrong kernel is worse than useless.

## profile.json schema (provisional, v0 — lock after the step-1 spike)

```json
{
  "run_id": "string",
  "variant_id": "string|null",        // null = baseline
  "kernel": "string",                  // kernel/op name or path
  "instance_type": "inf2.xlarge",
  "sdk_version": "2.29",
  "captured_at": "ISO-8601",
  "comparability_key": {               // two runs are comparable ONLY if these match
    "kernel": "...", "input_shapes": [...], "dtype": "...", "instance_type": "..."
  },
  "metrics": {
    "latency_us_p50": 0, "latency_us_p99": 0,
    "throughput_units_s": 0,
    "engine_utilization": {"tensor": 0.0, "vector": 0.0, "scalar": 0.0, "gpsimd": 0.0},
    "compute_vs_memory_bound": "compute|memory|balanced",
    "dma_throughput": 0,
    "top_ops": [{"name": "...", "latency_us": 0, "pct": 0.0}]
  },
  "correctness": {"verified": true, "rtol": 1e-3, "atol": 1e-3, "max_abs_err": 0.0}
}
```

Diff refuses (or warns loudly) when `comparability_key`s differ.

## Invocation contract (v0)

```
/neuron-optimize \
   --instance i-0abc... | --launch inf2.xlarge \   # existing box or spin one up
   --kernel path/to/kernel.py \                     # the variant target
   --inputs path/to/sample_inputs.npz \             # reference inputs for correctness
   [--seed "profiler suggestion text" | --auto] \   # variant seed
   [--max-variants 4] [--max-compile-retries 3] [--tol 1e-3]
```

Helper scripts (standalone, importable): `capture.py`, `parse.py`, `verify.py`,
`diff.py`, `cost.py`. The skill orchestrates; the scripts do the work.

## Premises

1. The capture toil is real and worth removing/automating. ✅
2. AWS owns capture + single-profile analysis + *suggestions*; we own the autonomous
   generate→verify→profile→rank **loop**. ✅
3. Skill-first is fine despite no-CI/Claude-only, *because* helpers are extractable. ✅
4. **Correctness gate before speed gate is non-negotiable.** ✅
5. **(Contingent, not settled.)** Whether we orchestrate our own capture or call AWS's
   `neuron-nki-profiling` for measurement is decided AFTER the step-1 hands-on run, based
   on what its JSON emits and whether it covers our kernels. Do NOT pre-commit. ⏳
6. Leading with kernel code-gen re-aims at the NKI/kernel-author audience; accepted. ✅

## Roadmap (one by one)

- **v0 — Prove the loop on ONE kernel.** Baseline measure → Claude generates 1 variant →
  compile gate → correctness gate → profile → diff → report. Even N=1 proves the "whoa":
  an AI produced a verified-correct, measurably-different kernel by itself.
- **v1 — Scale + rank.** N variants, bounded search, early-stop, Pareto ranking
  (latency). Run-to-run diff + baseline history fall out here for free.
- **v2 — Cost framing.** Per-variant $/1M-units using **measured concurrent throughput**
  (not 1/latency) × instance $/hr from a pinned price table (region-aware). Rank by cost
  too.
- **v3 — Exploratory: CI regression gate.** Extract helpers into a headless CLI + GitHub
  Action; fail a PR that regresses a tracked metric. Gated on adoption — the Neuron-in-CI
  runner story (warm self-hosted runner vs per-PR spin-up, cost) is its own infra problem.
- **v4 — Stretch: model-level variants.** Apply the same loop to config/flags/parallelism
  at the whole-model level → re-reaches the deployer audience.

## Open Questions

1. **Measurement data source (prerequisite gate, not a nice-to-have).** `neuron-profile
   --output-format json` is deprecated in 2.29; Neuron Explorer is GUI-first with an
   unspecified export; the agentic `neuron-nki-profiling` skill emits JSON. v0 is NOT
   buildable until we confirm which source yields engine-utilization / compute-vs-memory
   fields. Resolve in step 1–3 of Next Steps; may force parsing Perfetto with reduced fidelity.
2. **Correctness tolerance + input generation** — what counts as "still correct" for FP
   kernels; how to get representative inputs (user-supplied vs synthesized).
3. **Compile-retry policy** — retries per variant, and how to summarize "no improvement
   found" gracefully.
4. **Cost/time of a sweep** — N variants × (compile + 2 runs) on a $/hr box. Need a budget
   ceiling and early-stop.
5. **Seed quality** — can we programmatically pull Explorer/agentic suggestions as seeds,
   or is the seed just "make this faster" + the profile?

## Success Criteria

- **v0:** on one real NKI kernel, the loop autonomously returns a variant that (a)
  compiles, (b) passes the numerical correctness gate vs the original, (c) has a measured
  profile diff vs baseline — with no manual steps after invocation. A shareable demo clip exists.
- **Correctness gate proven:** an intentionally-wrong injected variant is *rejected* by
  gate [3], not reported as a winner.
- **v1:** ranks N variants; picks the fastest correct one; respects `--max-variants` and
  early-stop; total spend stays under a stated ceiling.
- **v2:** cost deltas match hand-computed throughput×$/hr on a real instance type.
- **Adoption:** public repo + README + 60-sec demo; first external star/issue.

## Distribution Plan

- v0–v2: Claude Code skill in a public GitHub repo (SKILL.md + `scripts/`); install via
  clone into `~/.claude/skills/` or a Claude Code plugin (mirroring AWS's Neuron agentic
  package). README with the demo clip.
- v3: extract `scripts/` into a CLI (PyPI) + a GitHub Action; the CLI is the engine, the
  skill and Action are two front-ends.

## Next Steps (the assignment)

1. **Spin up the cheapest captureable instance** (`inf2.xlarge` or small `trn1`), pick ONE
   small NKI kernel, and run AWS's profiling + agentic-dev skills on it **by hand once**.
   Time every step, capture the JSON each tool emits. This is your toil baseline AND your
   measurement-source decision (OQ1) AND your v0 reference.
2. **Build the correctness gate first** (`verify.py`): run two kernels on the same inputs,
   assert numerical equivalence within tolerance. This is the load-bearing, novel-risk
   piece — prove it before anything else.
3. Lock the `profile.json` schema against the real JSON from step 1.
4. Wire v0: baseline → Claude 1-variant generate → compile → verify → profile → diff →
   report, on the step-1 kernel.
